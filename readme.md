To test your application with a simple artifact, I recommend starting with the **`profile`****→****`prd`****workflow**.

Your `main.py` defines several stages, and each stage depends on artifacts generated by previous stages.

## 1\. First, configure the technology stack

Run:

bash

```bash
python main.py profile --client react --server python --orm sqlalchemy --database postgresql
```

This establishes the technology stack:

- Frontend: React
- Backend: Python
- ORM: SQLAlchemy
- Database: PostgreSQL

If your profile workflow asks additional questions, answer them interactively.

## 2\. Generate a simple PRD

Use this sample requirement:

bash

```bash
python main.py prd "Build a simple Task Management application where users can create, view, update, delete, and mark tasks as completed. Each task should have a title, description, due date, and status. Users should be able to filter tasks by status."
```

This should generate your first Product Requirements Document.

Alternatively, use `--new` to start from scratch:

bash

```bash
python main.py prd "Build a simple Task Management application with CRUD operations and task status filtering." --new
```

## 5\. Quick test: Commands in sequence

If you want to test the entire workflow, execute these commands one by one:

bash

```bash
# 1. Configure technology stack
python main.py profile --client react --server python --orm sqlalchemy --database postgresql

# 2. Generate PRD
python main.py prd "Build a Task Management application with CRUD operations, task status tracking, and due dates."

# 3. Generate System Requirements
python main.py sysrs

# 4. Generate Software Requirements
python main.py srs

# 5. Generate Architecture
python main.py architecture

python main.py lld

```

**My suggestion:** For your first test, don't execute all eight commands immediately. Run `profile` and `prd` first. Verify that the artifacts are generated correctly in `output/profile/` and `output/prd/` before proceeding.

One important detail: Your application uses an LLM for authoring and reviewing artifacts, so make sure your `.env` configuration contains valid model/provider settings before running these commands.
